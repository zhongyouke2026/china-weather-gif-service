# 중여커 날씨 — 디자인 시스템

`weather_pipeline/render.py` 상단의 토큰이 이 문서의 전부입니다. **새 값을 즉흥적으로 만들지 말고
아래 4개 스케일에서만 고르세요.** 이 규칙 하나가 "전문가 손길" 여부를 가릅니다.

## 1. 색 — 액센트는 하나뿐

| 역할 | 토큰 | 값 |
|---|---|---|
| 본문 | `LABEL` | `#1D1D1F` |
| 보조 값 | `LABEL_SECONDARY` | `#565B62` |
| 캡션·단위·출처 | `LABEL_TERTIARY` | `#8B9199` |
| 액센트 (측정된 데이터) | `ACCENT` | `#0071E3` |
| 경고 (태풍) | `ALERT` / `WARM` | `#FF3B30` / `#FF9500` |
| 바다 | `OCEAN` | `#E6ECF2` |
| 주변국 육지 | `LAND` | `#F0F2F5` |
| 중국·대만 육지 | `LAND_SUBJECT` | `#FCFDFE` |

원칙:

- **채도 높은 색은 날씨에만 씁니다.** UI 크롬은 전부 무채색 + 액센트 1개.
- **주제(중국)는 테두리 굵기가 아니라 명도로 구분합니다.** 주변국은 바다보다 한 단계 어둡게,
  중국·대만은 무엇보다 밝게. 기존의 1.65pt 파란 테두리는 강수 데이터와 경쟁했습니다.
- 기온 색은 4단계만 (`_temperature_color`): 12℃ 이하 / 보통 / 27℃ 이상 / 30℃ 이상.

## 2. 타이포 — 7단계, 굵기 2종

```
TYPE_STAMP 30 · TYPE_STAMP_SUB 17 · TYPE_HEADING 11 · TYPE_VALUE 10.5
TYPE_BODY 9.5 · TYPE_LABEL 9.5 · TYPE_CAPTION 7.6 · TYPE_MICRO 6.6
```

굵기는 `WEIGHT_BOLD`(제목·수치)와 `WEIGHT_REGULAR`(그 외)뿐입니다. 기존 코드에 있던
8.1 / 7.3 / 5.6 / 5.4 / 5.0 / 4.8 같은 중간값은 전부 없앴습니다. `semibold`는 CJK 폰트에서
굵기가 보장되지 않아 쓰지 않습니다.

프레임에서 가장 큰 글자는 **타임스탬프**입니다. 제목이 없으므로 시각이 곧 헤드라인입니다.

### ⚠️ 한글에는 `fontweight="bold"`가 먹지 않습니다

한글 폰트는 대부분 `.ttc` 컬렉션으로 배포되고 matplotlib은 그 안에서 **face 하나만** 등록합니다.
macOS의 Apple SD Gothic Neo는 등록된 굵기가 400 하나뿐이라, `normal` / `bold` / `black`을 뭘 넣든
같은 파일로 해석됩니다 — 즉 **볼드 지정이 아무 효과가 없습니다.** 이것이 예전 프레임의 글자가
흐릿해 보이던 진짜 이유였습니다.

```python
font_manager.findfont(FontProperties(family=F, weight="normal"))
 == font_manager.findfont(FontProperties(family=F, weight="bold"))   # macOS에서 True
```

그래서 `_text_effects()`가 **글리프 외곽선을 같은 색으로 덧그어** 굵기를 직접 만듭니다
(획 두께 = 폰트 크기 × 0.075). 진짜 볼드 페이스가 있는 환경(리눅스 CI의 Noto Sans CJK KR)에서는
`SYNTHETIC_BOLD`가 False가 되어 덧긋지 않으므로, 어느 machine에서 렌더해도 굵기가 같습니다.

지도 위에 놓이는 글자에는 같은 함수가 흰색 후광(폰트 크기 × 0.22)도 함께 넣습니다. 두 획 모두
폰트 크기에 비례하므로 6.6pt 캡션부터 30pt 타임스탬프까지 시각적 무게가 일정합니다.

## 3. 공간 — 1000×618 기준 픽셀 그리드

### 캔버스 높이는 눈대중이 아니라 계산값입니다

지도는 `set_aspect("auto")`로 캔버스를 꽉 채웁니다. 그래서 **캔버스 자체가 투영의 비율을 갖고
있어야** 하고, 아니면 중국이 납작해집니다. Plate Carrée에서 경도 1°는 위도 1°가 덮는 거리의
cos(위도)배이므로:

```python
height = width * (위도 범위 / 경도 범위) / cos(중앙 위도)
       = 1000 * (33 / 64) / cos(33.5°)  =  618
```

눈대중으로 고르면 이렇게 됩니다 — 실측한 형태 비율(1.000이 정확):

| | 형태 비율 | |
|---|---|---|
| 원본 1000×625 | 1.139 | 가로로 14% 늘어남 |
| 상단만 자르고 높이를 눈대중(1000×520) | 1.189 | 가로로 19% 늘어남 |
| **`canvas_height()` 계산값 (1000×618)** | **1.001** | **정확** |

`canvas_height(settings)`가 `Settings.bounds`에서 직접 계산하므로, 앞으로 뷰포트를 바꿔도 왜곡이
다시 생기지 않습니다. 덤으로 세로 여유가 생겨 라벨 배치도 좋아졌습니다(붙어있는 도시 16 → 18개).

모든 크롬 좌표는 참조 캔버스 기준 **픽셀 정수**이고 4px 그리드에 맞춥니다. 여백은 `MARGIN = 24`로
통일. `_Chrome` 헬퍼가 실제 캔버스 크기에 맞춰 한 번에 스케일하므로 다른 해상도에서도 비율이
유지됩니다. 세로 좌표는 **아래에서 위로** 잽니다(카드가 전부 좌하단에 있으므로). 상단에 고정되는
타임스탬프만 `_Chrome.from_top()`으로 변환합니다.

크롬을 axes 비율(0~1)이 아니라 **디스플레이 좌표**로 그리는 이유: axes 비율에서는 반지름 r이
가로 1000·세로 618로 늘어나 모서리가 타원이 됩니다. 디스플레이 좌표에서는 12px이 양방향 12px입니다.

## 4. 표면 — 스타일 1종

`_Chrome.card()` 하나만 씁니다: 불투명에 가까운 흰색 + 헤어라인 1개 + 부드러운 그림자 1개.
반지름은 `RADIUS_CARD 12` / `RADIUS_SMALL 7`, 알약형은 높이의 절반.

기존의 가짜 프로스티드 글래스(반투명 + 쿨 헤어라인 + 흰 스펙큘러 스트로크 + 그림자 4중첩)는
GIF에서 뭉개지기만 하고 깊이감을 주지 못해 제거했습니다.

## 5. 도시 캡슐

77×19pt 고정 알약. 3칼럼(아이콘 / 도시명 / 기온)이며 기온이나 날씨가 바뀌어도 **치수·타이포가
절대 변하지 않습니다**. 세로 카드(56×32pt)에서 가로 캡슐로 바꾸면서 면적이 줄어 밀집한 동남
해안의 배치 여유가 크게 늘었습니다.

칼럼 폭은 짐작이 아니라 **실측값**에서 나옵니다. 지도에 나오는 가장 긴 도시명 `타이베이`가
TYPE_LABEL에서 32.8pt, 가장 긴 기온 `-15°`가 TYPE_VALUE에서 16.7pt입니다.

```
4 pad │ 12 아이콘 │ 3.5 │ 33 도시명 │ 3.5 │ 17 기온 │ 4 pad  =  77
```

여백과 아이콘을 이렇게까지 조인 이유: 캡슐 폭 1pt가 늘 때마다 남동 해안의 라벨 배치가 나빠집니다.
실제로 글자를 키우면서 캡슐을 82×20으로 잡았더니 붙어있는 도시가 17→14개로 줄고 싼야가 136px까지
밀려나서, 글자 크기는 유지한 채 캡슐만 77×19로 되돌렸습니다.

배치 알고리즘(`_resolve_city_layout`):

1. **혼잡도 순 배치** — 이웃까지의 거리로 가중한 압력이 높은 도시(홍콩·선전·마카오·광저우)가
   먼저 자리를 고릅니다. 늦게 고르는 도시가 멀리 밀려나므로, 주변이 빈 도시에게 밀림을 넘깁니다.
2. **후보 정렬 기준은 실제 점–캡슐 간격** — 기존에는 링 순서로 훑어 "충돌은 없지만 아주 먼" 자리가
   가까운 자리를 이겼습니다. 지금은 모든 후보를 실제 간격으로 정렬합니다.
3. **개선 패스** — 전부 배치한 뒤 최악부터 다시 꺼내 재배치하고, 더 가까워질 때만 채택(3라운드).

결과: 22개 도시 중 18개가 점에 붙고, 최악값 74px → 49px, 총 이탈 521 → 298px.

`City.label_offset`(`qweather.py`)은 **선호 방향 힌트**일 뿐 규칙이 아닙니다. 자리가 있으면 존중하고
없으면 페널티(가로 10 / 세로 6)만 물고 다른 쪽으로 갑니다.

리더 라인은 간격이 `CITY_LEADER_MIN_PX`(10px)를 넘을 때만 그립니다. 붙어 있으면 선이 없고,
멀면 **보이는** 헤어라인이 생깁니다. 기존엔 모든 카드에 38% 알파의 안 보이는 선을 그렸습니다.

리더는 AnnotationBbox의 화살표가 아니라 **별도 선**(`Z_CITY_LEADER = 34`)으로 그립니다.
AnnotationBbox는 화살표를 자기 zorder에 그리기 때문에, 타이베이(primary, z38)의 리더가 아래쪽
가오슝 캡슐(secondary, z36) 글자 위를 가로지르는 문제가 있었습니다. 별도 레이어로 내리면 모든
캡슐 아래를 지나가므로 가리키는 캡슐 뒤로 자연스럽게 사라집니다.

## 6. 레이아웃 영역

제목 띠를 없애고, 정보를 **좌상단 타임스탬프**와 **좌하단 정보 컬럼** 두 곳으로 모았습니다.
나머지는 전부 지도입니다.

```
좌상단  26px  8월 22일 (토) 08:00     ← 30pt, 프레임에서 가장 큰 글자
        80px  1일 후                  ← 17pt 액센트
       118px  [미리보기]              ← demo 모드에서만

좌하단  아래에서 110px  태풍 현황 카드 (헤더 38 / 행 56 / 푸터 30)
        아래에서  30px  강수 범례 카드          ← 두 카드 모두 폭 272로 통일
        아래에서  15px  출처 한 줄
        바닥       3px  진행바 (풀블리드)
```

타임스탬프 세 줄의 간격은 눈대중이 아닙니다. 실측 렌더 높이가 각각 36px / 21px / 12px이므로
줄 사이를 18px씩 띄워야 한 덩어리로 뭉쳐 보이지 않습니다. 예약 영역(`STAMP_BLOCK_WIDTH` 360px)은
가장 긴 날짜 문자열 `12월 21일 (월) 17:00`(341px)을 기준으로 잡았습니다 — 월/일 자릿수가 늘어도
캡슐이 침범하지 않습니다.

정보 컬럼을 좌하단에 둔 이유: 티베트·신장은 지도에서 도시가 하나도 없는 유일한 넓은 영역입니다.
하단 중앙에 두면 싼야·광저우 캡슐을 밀어냅니다. 출처를 우하단에서 좌하단으로 옮긴 이유도 같습니다 —
우하단은 태평양 태풍이 화면에 들어오는 바로 그 자리입니다.

태풍이 없어도 패널 자리는 예약합니다(`_label_reserved_boxes`). GFS 런마다 태풍 개수가 달라져도
도시 배치가 흔들리지 않게 하기 위해서입니다.

## 7. 제거한 것

- **제목 `중여커 날씨`와 부제** — 프레임 상단 전체를 쓰면서 매 프레임 같은 말을 반복했습니다.
  브랜딩은 이 GIF를 싣는 페이지가 이미 하고 있습니다.
- **상단 여백** — 뷰포트를 55°N → 50°N으로 잘랐습니다. 잘려나간 구간은 몽골·러시아와 도시가 없는
  중국 동북 끝자락뿐입니다(최북단 도시 하얼빈 45.8°N). 프레임 높이는 625 → 618px로 거의 그대로지만,
  없어진 제목 띠와 잘려나간 빈 하늘만큼 **지도가 차지하는 면적이 커졌습니다**.
  `Settings.top_lat`을 바꾸면 GFS 다운로드 범위와 캔버스 높이가 함께 따라옵니다.
- `중국` 워터마크(40pt, alpha 0.075) — 노이즈.
- 강수 범례의 3개 스와치 — 지도는 8단계를 칠하면서 범례는 3단계만 보여줘 10mm와 80mm를 구분할 수
  없었습니다. 실제 8단계 그라데이션 바 + 경계값 눈금으로 교체.
- `_draw_typhoon_info_pill`, `_draw_typhoon_route_legend` — 호출되지 않는 죽은 코드.
